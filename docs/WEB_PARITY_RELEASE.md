# Общие функции Jospar: мобильное приложение и сайт

В мобильном приложении подключены:

- настройки проекта (название, код, описание, даты, закрепление), участники и роли;
- настройки workspace (название, цвет, логотип), участники и роли;
- архивирование, восстановление и удаление проектов/workspace с подтверждением;
- лента упоминаний, реакций и непрочитанных личных сообщений по кнопке уведомлений;
- обсуждения и сохранённые сообщения; действия сообщения по удержанию: сохранить, копировать, изменить и удалить своё сообщение;
- настройки каналов: название, участники, выход и удаление;
- метки и личные метки задачи, выбор эпиков, ресурсы (план/факт), загрузка, скачивание и удаление файлов;
- общие настройки вида карточек для пользователя, workspace, проекта и вида доски.

Используются существующие API и серверная проверка прав. Уведомления в этом изменении — лента внутри приложения; доставка системных push в фоне сюда не входит.

Порядок выпуска:

1. Выполнить обычную процедуру резервирования базы и применить миграции сервера (`npm run db:deploy` в `orbita-back`).
2. Сгенерировать Prisma Client и собрать сервер (`npm run db:generate`, `npm run build`), выпустить сервер штатным способом.
3. Собрать и выпустить сайт (`npm run build` в `orbita-front`).
4. Установить обновлённое мобильное приложение.

## Проверка синхронизации после выпуска

Под одним аккаунтом открыть одинаковый проект в сайте и приложении. Изменить вид карточек на одной стороне и вернуться на другую: приложение перечитывает настройки при возврате, сайт — при фокусе и периодически (30 секунд). Переключить пользователя и проект: настройки должны оставаться раздельными. При отсутствии сети изменения сохраняются локально и повторно отправляются при обновлении после восстановления сети.

Сохранение вида проверяет userId активного аккаунта на сервере, доступ к workspace и проекту, а также принадлежность проекта workspace. Обновления объединяются транзакционно, чтобы мобильный клиент не стирал поля, доступные только в вебе.
