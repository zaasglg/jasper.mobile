# Совпадение данных дашборда с веб-версией

Проверено 24 ноября 2026 года по публичному веб-клиенту:
`https://josparbee.kz/_next/static/chunks/app/(dashboard)/dashboard/page-b4e17f33f1248f5e.js`.

Мобильная реализация отличалась от веб-клиента в трёх местах:

- В общем KPI считала основные проекты вместе с подпроектами. Веб передаёт количество корневых проектов. Для выбранного фильтра по проектам учитывается размер выбранной области; задачи подпроектов входят в общий список.
- Загружала обычный `project-tasks` вместо используемого сайтом `project-tasks/timing`. Timing исключает задачи архивных проектов/пространств и архивных или удалённых колонок. Используется постраничная загрузка по 100 с фильтрацией полученных задач по проектам текущей области. Страница из других пространств не должна прерывать загрузку следующих страниц.
- Признавала завершённым статус `DONE` независимо от прогресса. Веб-функция завершённости (модуль 65038, используемый также 18787) проверяет только `progress >= 100`. Колонка и выполнение — разные признаки. Мобильные проектные задачи и дашборд теперь используют это же правило. Выполнение записи ежедневника остаётся отдельным полем.

Регрессии: `dashboard_data_parity_test.dart`, `dashboard_layout_test.dart` (API contract), `project_models_test.dart`, `projects_cubit_test.dart`, `dashboard_scrum_widget_test.dart`.

Реальные числа аккаунта не сверялись авторизованными запросами. Изменение устраняет подтверждённые различия алгоритмов; для численного сравнения должны совпадать аккаунт, область пространств, фильтр проектов и время обновления.
