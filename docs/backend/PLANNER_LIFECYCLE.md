# Независимость ежедневника от задач проекта

> Историческое предложение, не текущий контракт мобильного клиента.
> 26 ноября 2026 по запросу пользователя мобильный чекбокс приведён к вебу:
> проектная задача — `PATCH project-tasks/:taskId` с `progress: 100/0`,
> Инбокс и личная запись — `PATCH project-planner/items/:id` с `completed`.
> Проектный статус читается из `task.progress`, Инбокс — из
> `inboxTask.detail.completed`, личный — из `completed` записи.
> Маршрут `/completion` больше не вызывается; приведённый ниже патч не требуется
> для этой реализации. Независимый архив записей не менялся.

Мобильное приложение хранит выполнение и архивирование в записи ежедневника.
Статус, прогресс и архив исходной задачи не заменяют эти поля. Ссылка на исходную
карточку сохраняется: закрытие задачи проекта выполняется в её карточке.

## Серверная часть

`planner-independent-lifecycle.patch` подготовлен для `zaasglg/orbita-back` на
коммите `98f4a443d30d79f665d8437f144caa81639efbb5`. Рабочая копия с изменениями
находится в `.dart_tool/planner-backend` мобильного проекта. Она игнорируется Git;
патч сохраняет серверный код и тесты для переноса в серверный репозиторий.

Патч:

- сохраняет `completed` на `ProjectPlannerItem` для всех типов записей;
- убирает изменения `projectTask.progress` и `inboxTask.detail.completed`;
- сохраняет проверки личного доступа и доступа к текущему проекту исходной задачи;
- разрешает назначенному пользователю отмечать свой план без права закрывать проектную задачу;
- фильтрует архив по записи ежедневника, включая проверку занятости и экспорт Google;
- добавляет `PATCH project-planner/items/:itemId/completion` с обязательным булевым `completed`.

Существующие поля базы данных подходят, миграция схемы не требуется. Старое
выполнение проекта не переносится в ежедневник: оно не доказывает выполнение
личного плана. Удаление исходной задачи и потеря доступа к проекту сохраняют
существующее поведение сервера; этот патч меняет выполнение и архивирование.

## Порядок установки

Сначала применить и развернуть серверную часть, затем выпустить мобильное приложение.
В чистой рабочей копии серверного репозитория выполнить (подставить путь к патчу):

```powershell
git apply --check "C:/path/to/orbita-mobile/docs/backend/planner-independent-lifecycle.patch"
git apply "C:/path/to/orbita-mobile/docs/backend/planner-independent-lifecycle.patch"
npm.cmd ci
node node_modules/prisma/build/index.js generate
node node_modules/typescript/bin/tsc --noEmit --incremental false
node node_modules/jest/bin/jest.js --runInBand src/project-planner/planner-independent-completion.spec.ts src/project-planner/planner-update-transaction.spec.ts src/project-planner/planner-inbox.spec.ts src/project-planner/planner-list-access.spec.ts src/project-planner/planner-account.spec.ts src/google-drive/google-planner-sync.spec.ts
```

Без обновления сервера мобильное приложение отклоняет отметку связанной записи
через новый маршрут. Оно не повторяет запрос через старый маршрут, который мог
закрыть исходную задачу. Ошибка отображается пользователю, отметка откатывается.
Личные записи без связи с задачей продолжают использовать существующий маршрут.

## Проверки

Серверная проверка TypeScript проходит. Новые тесты проверяют оба значения
выполнения для проекта и Инбокса, совместное изменение времени и выполнения,
права доступа и валидацию нового маршрута.

В расширенном серверном прогоне осталось 27 падений в старых тестах чек-листов,
OCR, вместимости и названий. Они воспроизводились на исходном коммите;
новых падений по сравнению с ним нет. Результаты сравнения сохранены локально
в `.dart_tool/planner-backend-baseline.json` и `.dart_tool/planner-backend-after.json`.

Рабочий сервер не изменён. Проверки выполнены на подставном API и моках базы данных.
