# Настройки мобильных уведомлений

Мобильный интерфейс: Настройки → Уведомления. Выбор хранится отдельно для каждого аккаунта на устройстве. Категории: сообщения, упоминания, напоминания о сроках из ежедневника. Тихие часы действуют ежедневно, включая интервал через полночь. Совпадающие начало/конец означают весь день. Входящие звонки не блокируются. Сообщения и события внутри приложения не удаляются.

## Серверная установка

Патч `mobile-notification-preferences.patch` исходно подготовлен к backend `5e60cfa` (существующие push-компоненты обязательны). 24 ноября 2026 года он применён к актуальному backend и развёрнут в production коммитом `b1bb19b`. Миграция `20261124103500_mobile_notification_preferences` применена после резервного копирования базы. Firebase сконфигурирован; API без авторизации возвращает `401`.

1. Применить патч в репозитории backend, проверить diff и тесты `npm test -- --runInBand src/push`.
2. Выполнить штатное развёртывание Prisma-миграции `20261124103500_mobile_notification_preferences`, генерацию Prisma Client и сборку сервера.
3. Развернуть сервер, затем полную нативную сборку приложения.

Новый API: `PUT /push/mobile/preferences` с `{token, preferences}`; ответ `{saved:true}`. Настройки принимает только активная авторизованная сессия, которой принадлежит указанный токен устройства. Пользовательский ID от клиента не принимается. Настройки содержат булевы `messages`, `mentions`, `deadlines`, `quietEnabled`; минуты суток `quietStart`/`quietEnd`; часовой пояс IANA `timeZone` и резервный `utcOffsetMinutes`. Часовой пояс передаётся нативной платформой и обновляется при возврате в приложение. Сервер применяет правила DST.

Фильтрация выполняется непосредственно перед отправкой FCM, включая повторы очереди. Отключённое уведомление помечается обработанным, утреннего накопленного повтора нет. Привязка токена к новой сессии сбрасывает прежние настройки до следующей синхронизации.

Планировщик существующих напоминаний ежедневника ставит уведомления в мобильную очередь независимо от наличия VAPID для веба. Повторная постановка защищена существующим уникальным ключом доставки. Перед отправкой снова проверяются владелец, доступ, выполнение, архив и актуальность времени напоминания. Push не отправляется после наступления события. Нажатие открывает ежедневник.

## Поведение без обновления сервера

Android фильтрует показ локально, включая фоновое получение data-сообщений. iOS фильтрует уведомления в открытом приложении; фоновые APNs-баннеры формирует система, поэтому для них необходим серверный патч. Если сервер ещё не поддерживает API или недоступен, приложение явно показывает, что настройки сохранены на устройстве, но фоновые уведомления не синхронизированы, и предлагает повторить.

Не удалять разрешения ОС и существующие токены при смене настроек. Для проверки реальной доставки требуются настроенный Firebase и физическое iOS-устройство.
