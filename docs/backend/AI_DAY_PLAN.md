# План дня через AI

Внизу AI-чата, в строке действий поля ввода, иконка календаря «План дня через AI» открывает предложение на сегодняшний
день в часовом поясе устройства. AI выбирает до пяти назначенных пользователю
незавершённых проектных задач, объясняет выбор и оценивает длительность. Сроки
и приоритеты берутся из существующих задач. Пользователь может исключить задачи,
изменить длительность и задать время перед подтверждением.

## Сервер

`ai-day-plan.patch` подготовлен к `zaasglg/orbita-back` на коммите
`5e60cfa306ef5495a6c443cae52d975d701cb0b9`. Проверенная рабочая копия находится в
`.dart_tool/message-status-backend`. Патч включает только новый сценарий AI-плана
и его регистрацию; изменения уведомлений и сообщений в него не входят.

Новый `POST ai/assistant/day-plan` принимает:

```json
{"workspaceId":"workspace-id","date":"2026-11-24"}
```

Запрос требует JWT и доступа к пространству. Сервер проверяет доступ к проектам,
исключает архивные проекты и колонки, завершённые задачи, задачи с будущим началом
и любые задачи, уже связанные с ежедневником. Кандидаты ограничены 100 задачами:
сначала ближайшие сроки, затем приоритет. Inbox в первой версии не участвует.

Модель вызывается напрямую без инструментов и без записи данных приложения.
Проверяются ID, повторения, длительность и общий бюджет предложения (до 240 минут).
Названия, проекты и сроки в ответе берутся из базы, а не из ответа модели.
Длительность и объяснение — оценка модели. Ограничение частоты: пять запросов
в минуту на пользователя на процесс сервера. Используются существующие
`DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL`; новых секретов или миграций нет.

В чистой рабочей копии backend:

```sh
git apply --check /path/to/jospar/docs/backend/ai-day-plan.patch
git apply /path/to/jospar/docs/backend/ai-day-plan.patch
node node_modules/typescript/bin/tsc --noEmit --incremental false
node node_modules/jest/bin/jest.js --runInBand src/ai/services/ai-day-plan.service.spec.ts
```

После проверки развернуть backend обычным процессом проекта, затем выпускать
мобильный клиент. Без обновления сервера клиент показывает понятную ошибку
вместо обращения к AI-чату, который умеет выполнять действия.

## Подтверждение

Только явное подтверждение добавляет ссылки на исходные задачи через существующий
`PlannerRepository.addTask`; исходные названия, сроки, прогресс и статусы задач
не изменяются. По умолчанию план сохраняется без времени через API `day-tasks`.
Для него требуется серверная поддержка из `PLANNER_WITHOUT_TIME.md`.

Перед сохранением клиент перечитывает ежедневник. Уже связанные задачи оставляет
без изменений, включая записи на другие дни. При указании времени проверяются
пересечения между предложениями и записями из `PlannerRepository.load`, а также
прошедшее время. Отдельно загруженные события Google Calendar в эту проверку
не включены; проверка занятости на сервере остаётся окончательной.

Сохранение последовательное: при ошибке уже подтверждённые записи остаются
отмеченными, остальные можно изменить и повторить попытку. При неоднозначной
ошибке повторная попытка сначала перечитывает ссылки. Проверка перед сохранением
не является общей транзакцией с другими устройствами: конкурентное изменение
после проверки обрабатывается существующим API ежедневника.

Черновик не сохраняется между открытиями. Закрытие отменяет запрос к AI;
при смене аккаунта, пространства или календарного дня сохранение блокируется.
История обычного AI-помощника не меняется.

## Проверки

Flutter-тесты: предложение не пишет данные; редактирование и исключение задач;
подтверждение; частичное сохранение и повтор; сохранённая запись на другом дне;
смена пространства; поздний ответ; отмена; двойное нажатие; конфликты времени;
некорректный ответ; запуск из AI-чата и отмена; узкий экран и крупный текст.

Серверные тесты: доступ, фильтрация кандидатов, отсутствие инструментов,
канонические поля задач, валидация ответа модели и дат, ошибки AI и лимит запросов.
