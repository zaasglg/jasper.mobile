# Автоматическое обновление мессенджера

Используется существующий HTTP API без изменений сайта и сервера:
открытая переписка опрашивается каждые 10 секунд, видимый список чатов —
каждые 15 секунд. Веб также использует периодический refetch (10/30 секунд).
Возврат на экран или возобновление приложения запускает обновление сразу.

Опрос активен только на соответствующем маршруте и при resumed lifecycle.
Сохранённые ветки нижней навигации и перекрытые маршруты не опрашиваются.
После прочтения/отправки уведомляется список чатов: при следующем показе
получает актуальные превью и счётчики. Отметка прочтения отправляется только
для видимой переписки и нового последнего сообщения; при ошибке повторяется.

Фоновый refetch не включает загрузчик и сохраняет историю при сетевой ошибке.
Параллельные загрузки объединяются. Версии запросов отбрасывают ответы,
полученные до изменения сообщения, смены workspace или выхода из аккаунта.
Повторяющиеся ID сервера не создают дубликатов. При смене workspace старая
переписка инвалидируется, отправка блокируется, пользователь возвращается
к списку чатов. При поступлении сообщений сохраняется позиция чтения истории;
список использует стабильные ключи сообщений.

Проверки: 64 теста чата, workspace и запуска приложения; flutter analyze.
В частности, проверены таймеры, возобновление, скрытый маршрут, read receipts,
медленная сеть, восстановление, устаревший ответ во время отправки и смена
workspace. Набор использует подменённый API; реальные сообщения другим людям
во время проверки не отправлялись.

Это foreground-обновление; push при закрытом приложении остаётся отдельной
задачей. Полная история пока загружается существующим GET messages; отдельная
постраничная загрузка длинных переписок в это изменение не включалась.
