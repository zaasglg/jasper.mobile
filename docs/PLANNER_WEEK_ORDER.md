# Ручной порядок недельного планировщика

Плитки и список используют один локальный порядок внутри календарного дня.
Удержание текстовой области карточки начинает перенос; короткое нажатие открывает
редактор. Чекбокс и удаление находятся вне источника перетаскивания. Линия у края
карточки показывает вставку в порядке слева направо, затем сверху вниз.
Изменение порядка фиксируется только после успешного отпускания в исходном дне.
Отмена, отпускание вне дня и перенос в другой день ничего не сохраняют.

Используются встроенные `LongPressDraggable` и `DragTarget`. Сетка `Wrap` не заменена
списком. Прокрутка всей недели сохраняется; при удержании у края работает
автопрокрутка. Во время жеста исходная раскладка остаётся стабильной, а карточка
следует за пальцем с сохранением точки захвата. Для экранного диктора доступны
невидимые пользовательские действия «Переместить выше» / «Переместить ниже».

## Данные и изоляция

`PlannerWeekOrderCubit` проектирует уже загруженные `PlannerItemModel`.
Он не зависит от сетевого репозитория ежедневника и не изменяет его состояние.
Идентификатор порядка — `PlannerItemModel.id`, не `taskId`.
Время, продолжительность, дата, доска и дневное представление не меняются.

`PlannerWeekOrderRepositoryImpl` сохраняет JSON в существующем SharedPreferences:

```text
planner_week_order.v1.<account-id>.<view-scope>
```

```json
{"2026-11-26":["planner-item-3","planner-item-1","planner-item-2"]}
```

Текущий экран получает личную область через API account, поэтому его scope —
`account`. Для будущего workspace-представления передавать отдельный scope,
например `workspace:<id>`. Дата — местный календарный день. Начальный порядок
следует существующей сортировке по времени; после ручной перестановки новые записи
добавляются в конец. Удалённые, архивные и перенесённые в другой день записи
игнорируются. Сохраняемый снимок очищается при следующей перестановке.
Повреждённые данные читаются как пустой порядок либо фильтруются по строковым ID.

Смена аккаунта сбрасывает видимое состояние до чтения нового scope. Запоздавший
результат предыдущей загрузки/записи не применяется к новому аккаунту. Записи
хранилища последовательны; при ошибке сохранения порядок откатывается и выводится
сообщение. Между устройствами порядок не синхронизируется.

## Проверки

- `planner_week_order_test.dart`: изоляция аккаунта/области, повреждённый JSON,
  восстановление Cubit, обновления списка, удаление и перенос записи, откат записи.
- `planner_week_drag_test.dart`: плитки/список, отпускание, отмена, запрет переноса
  между днями, кнопки, обычная прокрутка, автопрокрутка, скрытые действия диктора,
  тёмная тема и крупный текст ru/kk.
- `planner_week_isolation_test.dart`: настоящий PlannerScreen, перестановка через
  жест, возврат в день, неизменность данных и ноль дополнительных запросов/записей
  PlannerRepository.

Выполнены автоматические проверки жестов в работающем iOS-симуляторе iPhone 17 Pro
Max (iOS 26.2), используя тестовый экран с подставными задачами без запросов к
серверу. Это не ручная проверка VoiceOver и не проверка на физическом устройстве.

Для повторения (подставить ID симулятора):

```sh
flutter test integration_test/planner_week_drag_test.dart -d <device-id> --no-uninstall
flutter test integration_test/planner_week_drag_test.dart -d <device-id> --no-uninstall --dart-define=WEEK_ORDER_RESTORE_ONLY=true
```

Первый запуск проверяет жесты и пишет тестовый порядок через настоящий плагин
SharedPreferences. Второй запускает новый процесс приложения, проверяет
восстановление и удаляет только собственный тестовый ключ. `--no-uninstall`
необходим: стандартное удаление integration-приложения удаляет и его контейнер.
Тестовая identity не читает и не перезаписывает токен входа.
