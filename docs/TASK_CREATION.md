# Создание задачи с дашборда

Верхний «+» открывает `/tasks/new`, а не каталог виджетов. Форма повторяет
поля веб-компонента `NewTaskModal`: название, workspace, проект/подпроект,
колонка, позиция, эпики, срок, оценка времени, участники и файлы.

Workspace формы не меняет глобально выбранный workspace приложения. Все
запросы проектов, колонок, эпиков, участников и создания передают явный
`X-Workspace-Id`. При смене workspace/проекта зависимые списки сбрасываются,
поздние ответы игнорируются; название, срок, время и файлы сохраняются.

Создание использует существующий `POST project-tasks`. Оценка считается так
же, как на сайте: рабочий день = 8 часов; `est` округляется до часов вверх,
`detail.estimateMinutes` хранит точные минуты. Вложения отправляются в
`detail.files` и обрабатываются существующим облачным interceptor. Лимиты:
10 МБ на файл и 35 МБ суммарно, чтобы JSON/base64 укладывался в серверные
50 МБ. Ошибка сохраняет черновик; повторная отправка в процессе блокируется.

Добавление в конец оставляет определение порядка серверу. Для промежуточной
позиции используется транзакционный `insertAfterTaskId`. Для первой позиции
в непустой колонке выполняется тот же batch-order, что в вебе. Если создание
прошло, а batch-order завершился ошибкой, форма возвращает созданную задачу
с предупреждением, не предлагает повторно создавать её и не дублирует POST.

После создания дашборд обновляет свои данные и «Мои задачи». Отмена формы
не меняет раскладку дашборда и не сохраняет её черновик.

Проверки: `flutter analyze`, тесты `task_creation_test.dart`,
`task_creation_screen_test.dart`, `dashboard_editor_test.dart`; сборка
`flutter build ios --simulator` с подписью для запуска в iOS Simulator.
