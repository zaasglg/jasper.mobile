# Аудио- и видеозвонки

Мобильное приложение использует существующие комнаты LiveKit и API сайта.
Ключи LiveKit не хранятся в приложении: сервер выдаёт краткоживущий токен
при создании комнаты или принятии приглашения.

## Подключено

- Кнопки аудио- и видеозвонка в личной переписке.
- Выбор участников для звонка в канале.
- Входящие во всём авторизованном приложении: принять, отклонить, аватар,
  звуковой сигнал. Запрос `GET video/rooms/incoming` раз в три секунды,
  только пока приложение находится на переднем плане.
- Проверка состояния комнаты перед принятием приглашения.
- Микрофон, камера, переключение камер, динамик/телефон.
- Видео участников и индикатор говорящего.
- Сворачивание экрана без отключения; баннер возвращения в звонок.
- Завершение комнаты инициатором и участником исходного личного звонка.
  Приглашённый участник групповой комнаты отключается только локально.
- Открытие активного звонка и повторный звонок из сообщения в переписке.
- Обновление сообщений после создания и завершения звонка.
- Проверка разрешений перед отправкой приглашений и освобождение устройств
  после отказа, отмены или ошибки соединения.

## Платформы и ограничения

На iOS включён background audio для уже начатого разговора. Мобильных
push-уведомлений о новых звонках при закрытом/приостановленном приложении
пока нет. Имеющийся серверный push реализует браузерный Web Push, а не
нативную доставку VoIP.

Для входящих при закрытом приложении потребуется серверная регистрация
мобильных устройств и доставка APNs/PushKit + CallKit на iOS, FCM и системный
экран входящего звонка на Android. На Android добавлен foreground service с типами microphone/camera: постоянное
уведомление, возврат в разговор, завершение из уведомления и сохранение
FlutterEngine при закрытии Activity во время активного звонка. Сервис
запускается после получения разрешений и останавливается при отключении.
Эти функции нельзя заменить постоянным таймером в Flutter.

Камеру следует проверять на физическом устройстве: iOS-симулятор не
предоставляет полноценную камеру для WebRTC.

## Проверка на двух устройствах

1. Войти двумя участниками одного workspace (приложение и сайт либо два телефона).
2. Начать аудиозвонок из личного чата; проверить входящий, двусторонний звук,
   отключение микрофона, динамик и завершение с обеих сторон.
3. Повторить видеозвонок, выключить камеру, переключить переднюю/заднюю.
4. Отклонить входящий и не отвечать до серверного тайм-аута; сверить сообщение
   о звонке с сайтом.
5. Проверить групповой звонок: выбранные участники, выход приглашённого
   без завершения для остальных, завершение инициатором.
6. Проверить отказ в разрешениях, сворачивание экрана и потерю сети.

Автотесты используют подменённый медиадвижок и HTTP-ответы и проверяют
контракты и состояния.

## Демонстрация экрана

В активном звонке кнопка «Экран» открывает системное разрешение на трансляцию.
Повторное нажатие «Остановить экран» прекращает только трансляцию; камера и
микрофон остаются включёнными. Передаётся изображение экрана без системного
аудио. Собеседник видит экран крупно без обрезки и может увеличить его жестом.
Камеры участников остаются в нижней ленте. Собственная трансляция заменена
индикатором, чтобы избежать бесконечного зеркала.

Android: разрешение MediaProjection запрашивается перед включением типа
`mediaProjection` фонового сервиса. Захват запускается после подтверждения
сервисом. При остановке трансляции тип проекции убирается. Отмена разрешения
не завершает звонок.

iOS: добавлено ReplayKit-расширение `com.jospar.app.ScreenBroadcast`, встроенное
в Runner, с общей группой `group.com.jospar.app`. Для запуска на устройстве
профили подписи Runner и расширения должны содержать эту App Group. В
системном окне нужно подтвердить начало трансляции. При завершении звонка
приложение отправляет расширению команду остановки. Этот механизм не требует
PushKit/APNs и не добавляет входящие звонки при закрытом приложении.

Проверка 31 октября 2026: отдельная комната настоящего LiveKit, два технических
участника, без приглашений людей. Браузер передавал синтетический экран,
Android API 36 — реальный захват экрана эмулятора. Подтверждены декодирование
в обе стороны, работа после Home, остановка кнопкой и отмена системного
разрешения с сохранением звонка. iOS: подписанная сборка симулятора с
ReplayKit-расширением проходит; захват на физическом iPhone не проверен,
поскольку устройство недоступно.

Результаты: [verification/screen-share-2026-10-31.json](verification/screen-share-2026-10-31.json).
Исходный транспорт ReplayKit взят из примера LiveKit Flutter 2.13.2; лицензия и
атрибуция находятся в `ios/ScreenBroadcast`. Версия SDK закреплена: используется
его внутренний BroadcastManager, пока он не экспортируется публично.

## Системный входящий звонок

Входящий, обнаруженный авторизованным приложением, показывается через
`CXProvider`/CallKit на iOS и `Notification.CallStyle` (Android 12+) на Android.
На более ранних Android используются действия обычного уведомления. Отдельных
пакетов и серверных изменений для этой интеграции не добавлено.

«Ответить» использует существующий `CallCubit.accept`, «Отклонить» и истечение
45 секунд ожидания — `decline`. Отмена на сервере закрывает системное
представление. Устаревшие действия другой комнаты игнорируются. При ошибке
или запрете нативного показа остаётся входящий внутри приложения.

CallKit получает события активации/деактивации `AVAudioSession`, передаваемые
в `RTCAudioSession` WebRTC. Его кнопка микрофона синхронизируется с приложением;
завершение из системного интерфейса освобождает медиа и завершает/покидает
комнату по существующим правилам. Hold, DTMF и объединение звонков отключены.

На Android нужны уведомления; для полноэкранного показа также нужен доступ
`USE_FULL_SCREEN_INTENT`. Android 14+ может запретить полноэкранный показ:
тогда используется CallStyle-уведомление с кнопками. Приложение не открывает
экран поверх блокировки в обход этого разрешения. Ответ возвращает в
существующую задачу приложения, не создавая второй Flutter Activity.

Это презентация уже доставленного звонка. Новые входящие при завершённом
процессе или при приостановке iOS без push не добавлены: APNs/PushKit и Firebase
по-прежнему отложены. Пока процесс выполняется, уже известный входящий/активный
звонок опрашивается и после сворачивания, чтобы обработать отмену.

Проверки: 79 тестов звонков, чата и корневого приложения; анализатор без ошибок;
подписанная сборка iOS-симулятора. Нативные действия Android проверялись на
отдельном эмуляторе с тестовым звонком без реальных участников. Полноценный
CallKit со звуком и камерой требует проверки на физическом iPhone.
