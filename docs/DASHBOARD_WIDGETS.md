# Редактирование дашборда

Мобильное приложение использует существующие API сайта:

- `GET dashboard/config?workspaceId=...`
- `PUT dashboard/config` с `{ workspaceId, layout }`

Конфигурация версии 2 содержит `widgets` (тип, instanceId, visible, size,
height, фильтры) и `layouts` (`lg`, `md`, `sm`). Мобильное приложение читает
порядок из `sm`. Перестановка и скрытие не меняют существующие координаты
`lg`/`md`. Добавленные экземпляры размещаются в свободном месте внизу
больших раскладок. Явное изменение размера меняет только выбранный виджет,
перенося его вниз, чтобы не перекрыть соседние. При отсутствии раскладки
используются правила сетки сайта: 12/8/1 колонок и минимальные высоты.

Неизвестные поля конфигурации и неподдерживаемые будущие типы сохраняются
при записи. Старый формат массива виджетов читается и переводится в v2.

## Интерфейс

Карандаш в шапке включает редактирование. Каталог открывается кнопкой
«Добавить виджет» внутри режима редактирования. Верхний «+» создаёт задачу.
В режиме редактирования виджеты можно перетаскивать за ручку или двигать
пунктами «Выше»/«Ниже». Меню виджета позволяет открыть настройки и скрыть
его. Скрытый виджет снова доступен в каталоге. Скрам, команда, ресурс и карта
поддерживают несколько экземпляров, как на сайте.

Сохраняются высота, ширина большого экрана и фильтры проектов. Скрам умеет
группировать задачи по колонкам/эпикам. Ресурс сохраняет тип отбора
(проекты/метки/эпики), показатели и отдельные настройки каждого проекта;
используются совместимые с вебом ключи меток и пар план/факт.

Изменения являются черновиком до «Сохранить». «Отмена» возвращает сохранённую
раскладку. При ошибке записи черновик остаётся открыт. Перед записью повторно
читается серверная конфигурация: если она изменилась на другом устройстве,
предлагается обновить дашборд вместо перезаписи. Это проверка перед записью;
существующий серверный API не предоставляет атомарный compare-and-swap.

Смена аккаунта/workspace очищает черновик и кэш данных. Поздние ответы старого
workspace игнорируются. В режиме просмотра конфигурация сверяется с сервером
каждые 30 секунд, при возобновлении приложения обновляются также данные.
В режиме редактирования фоновая синхронизация не подменяет черновик.

## Данные

Каталог соответствует типам сайта: AI, KPI, Скрам, активность, мои задачи,
команда, упоминания, ежедневник, ресурс и карта. Используются реальные
workspace-проекты, постранично загруженные задачи, участники, API активности,
упоминаний/реакций, ежедневника и ежедневного фокуса. Карта использует те же
координаты задач на Яндекс Картах через тот же JavaScript API, что и сайт.
Ключ и команды сборки описаны в `docs/YANDEX_MAPS.md`. Ошибки данных
отображаются внутри конкретного виджета с повтором загрузки. Получение
конфигурации с ошибкой не заменяет её стандартным набором для последующей
случайной перезаписи.

Веб и сервер для этого изменения не модифицировались. Геометрия и визуализации
адаптированы к мобильному экрану; исходные настольные настройки сохраняются.

## Проверка

`flutter analyze`

`flutter test test/features/dashboard`

`flutter test --concurrency=2`

`flutter build ios --simulator`

Для установки в iOS Simulator используйте сборку с подписью. Вариант
`--no-codesign` может оставить предсобранные media_kit framework без подходящей
подписи и привести к отказу загрузчика ещё до запуска Dart.
