# API ресурсов Orbita

Документ описывает текущий локальный код `orbita-back`. Доступность изменений на развёрнутом сервере не проверена.

## Подключение

Базовый URL: `https://<backend-host>/api`.

Все запросы требуют JWT и доступа к проекту задачи:

```http
Authorization: Bearer <access_token>
```

Для POST и PATCH добавьте `Content-Type: application/json`.

## Endpoints

| Метод | Путь относительно `/api` | Назначение |
| --- | --- | --- |
| GET | `/tasks/:taskId/resources` | Список ресурсов задачи |
| POST | `/tasks/:taskId/resources` | Создание ресурса |
| PATCH | `/resources/:id` | Редактирование и калькулятор |
| DELETE | `/resources/:id` | Удаление |
| GET | `/resources/:id/history` | История с пагинацией |
| GET | `/projects/:projectId/resources/summary` | Сводка проекта |
| GET | `/projects/:projectId/resources/names` | Названия для автодополнения |

## Поля создания и редактирования

| Поле | Тип | Правила |
| --- | --- | --- |
| `name` | string | Необязательное; до 120 символов; переданная строка после trim не должна быть пустой |
| `unit` | string | Необязательное; одно из значений ниже; при создании по умолчанию `pieces` |
| `customUnit` | string | До 40 символов; непустое при единице `custom` |
| `planValue` | decimal string или number | Неотрицательное значение, до 4 знаков после точки; при создании по умолчанию 0 |
| `factValue` | decimal string или number | Неотрицательное значение, до 4 знаков после точки; при создании по умолчанию 0 |

Для десятичных значений рекомендуется передавать строки, например `"125.25"`. Разделитель — точка, не запятая. Экспоненциальная запись не соответствует формату DTO.

| `unit` | Значение |
| --- | --- |
| `hours` | Часы |
| `days` | Дни |
| `personHours` | Человеко-часы |
| `pieces` | Штуки |
| `kilograms` | Килограммы |
| `liters` | Литры |
| `tenge` | Тенге |
| `custom` | Пользовательская единица из `customUnit` |

Для м³ используйте `unit: "custom"`, `customUnit: "м³"`. Для стандартных единиц backend сохраняет `customUnit` как null.

## 1. Список ресурсов

```http
GET /api/tasks/<taskId>/resources
```

Ответ — массив ресурсов с историей. Сортировка ресурсов: `order` по возрастанию, затем дата создания. В каждом ресурсе возвращается до 50 последних записей истории, сначала новые.

## 2. Создание ресурса

```http
POST /api/tasks/<taskId>/resources
Content-Type: application/json
```

```json
{
  "name": "Бетон",
  "unit": "custom",
  "customUnit": "м³",
  "planValue": "500",
  "factValue": "300"
}
```

Пример cURL; замените host, токен и ID задачи:

```bash
curl --request POST 'https://<backend-host>/api/tasks/<taskId>/resources' \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --data '{"name":"Бетон","unit":"custom","customUnit":"м³","planValue":"500","factValue":"300"}'
```

Возвращается созданный ресурс с историей. Максимум — 12 ресурсов на задачу. Один объект содержит и план, и факт.

Если название отсутствует, backend назначает: первому ресурсу — «План», второму — «Факт», следующим — «Ресурс N». Если значения плана или факта явно переданы, для них создаются записи истории установки базового значения.

## 3. Редактирование ресурса

```http
PATCH /api/resources/<resourceId>
Content-Type: application/json
```

Передавайте только изменяемые поля:

```json
{
  "name": "Бетон для фундамента",
  "planValue": "600",
  "factValue": "350"
}
```

Изменение единицы:

```json
{
  "unit": "custom",
  "customUnit": "м³"
}
```

При PATCH неуказанные поля сохраняют текущие значения. При переходе на `custom` нужна пользовательская единица: переданная либо уже сохранённая. Пустой запрос отклоняется. Возвращается обновлённый ресурс с историей.

### Калькулятор

Используется тот же PATCH. Пример: прибавить 25 к факту.

```json
{
  "calculation": {
    "target": "FACT",
    "operation": "ADD",
    "value": "25"
  }
}
```

`target`: `PLAN` или `FACT`.

| `operation` | Действие |
| --- | --- |
| `ADD` | Прибавить |
| `SUBTRACT` | Вычесть |
| `MULTIPLY` | Умножить |
| `DIVIDE` | Разделить |
| `SET` | Установить значение |

Операнд `value` допускает до 4 знаков после точки. Результат округляется до 4 знаков. Деление на ноль, отрицательный или нечисловой конечный результат запрещены. Отрицательный операнд допустим, если результат остаётся неотрицательным.

Нельзя одновременно передавать `calculation` и прямые `planValue`/`factValue`. Изменения чисел и операции калькулятора записываются в историю.

## 4. Удаление

```http
DELETE /api/resources/<resourceId>
```

Ответ:

```json
{
  "ok": true
}
```

## 5. История

```http
GET /api/resources/<resourceId>/history?take=20
```

| Параметр | Правила |
| --- | --- |
| `take` | Целое от 1 до 100; по умолчанию 50 |
| `cursor` | ID записи, после которой получить следующую страницу |

Структура ответа:

```json
{
  "items": [],
  "nextCursor": null
}
```

Если `nextCursor` не null, передайте его в следующем запросе:

```http
GET /api/resources/<resourceId>/history?take=20&cursor=<nextCursor>
```

Записи отсортированы от новых к старым. История включает `target`, `action`, `previousValue`, `newValue`, `formattedLog`, `createdAt`, `userId`, а также пользователя с полями `id`, `name`, `avatarUrl`. Текст журнала формируется с датой в часовом поясе `Asia/Almaty`.

## 6. Сводка проекта

```http
GET /api/projects/<projectId>/resources/summary
```

Необязательные фильтры:

| Параметр | Формат |
| --- | --- |
| `taskIds` | ID задач через запятую, максимум 4000 символов |
| `resourceIds` | ID ресурсов через запятую, максимум 4000 символов |
| `names` | Названия через запятую, максимум 1000 символов |

При передаче нескольких фильтров они применяются совместно. Архивные задачи исключаются.

```http
GET /api/projects/<projectId>/resources/summary?taskIds=task_1,task_2&names=Бетон
```

Пример ответа для одного ресурса с планом 500 и фактом 300:

```json
{
  "count": 1,
  "planTotal": "500",
  "factTotal": "300",
  "difference": "-200",
  "differencePercent": "-40"
}
```

Формулы:

```text
difference = factTotal − planTotal
differencePercent = (factTotal − planTotal) / planTotal × 100
```

При нулевом плане `differencePercent` равен null. Это процент отклонения, а не процент использования.

Текущая реализация суммирует ресурсы без группировки по единице измерения. Для осмысленного результата выбирайте совместимые ресурсы: сумма денег и часов не имеет общей единицы.

## 7. Названия для автодополнения

```http
GET /api/projects/<projectId>/resources/names
```

Необязательный параметр `target`: `PLAN` или `FACT`.

```http
GET /api/projects/<projectId>/resources/names?target=PLAN
```

Пример ответа:

```json
["Бетон", "Бюджет", "Работа дизайнера"]
```

Backend рассматривает 200 последних обновлённых ресурсов проекта и возвращает до 50 уникальных названий. Дубликаты сравниваются без учёта регистра. В этом endpoint архивные задачи явно не исключены.

Особенность текущего кода: фильтр `target` определяется по `order` ресурса — чётный порядок считается `PLAN`, нечётный `FACT`. Это не фильтрация по наличию планового или фактического значения.

## Ошибки и ограничения

- Все маршруты защищены JWT и проверкой доступа к проекту.
- Неизвестная задача или ресурс: `404`.
- Ошибки DTO и бизнес-валидации: `400`, в том числе пустое переданное название, превышение лимита ресурсов, деление на ноль, отрицательные значения, отсутствие пользовательской единицы и несовместимые поля калькулятора.
- Отдельных endpoints для дублирования и получения одного ресурса в этом контроллере нет. Для дублирования создайте новый ресурс через POST с копией полей.
- Поле процента использования не принимается DTO; интерфейс может вычислять `factValue / planValue × 100` при положительном плане. Отображение «—» при нулевом плане — правило интерфейса, не поле API.
